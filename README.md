# T-Display PasswordsBox

Портативный гаджет на базе **LilyGo T-Display S3** для автоматического ввода учётных данных (логинов и паролей) через USB (HID). Устройство распознаётся компьютером как обычная клавиатура.

## 📝 Описание

Устройство отображает список аккаунтов на TFT-экране. Аккаунт выбирается касанием по экрану. При нажатии физической кнопки гаджет имитирует набор текста: короткое нажатие левой кнопки — логин, `TAB`, пароль и `Enter`, короткое нажатие правой — только пароль и `Enter`.

Для защиты данных при каждом запуске устройство может запросить **пин-код**, распознать отпечаток пальца датчиком **R503-S** или использовать оба способа. Список паролей появляется только после успешной разблокировки.

В прошивку встроен **служебный режим управления отпечатками**: если при включении удерживать правую кнопку и ввести пин-код, устройство открывает менеджер датчика (запись, проверка, список, удаление). Отдельная прошивка для этого больше не нужна.

## 🚀 Основные возможности

- **🔒 Защита при запуске**
  - Активен только один способ разблокировки. При одновременном включении `ENABLE_PIN_CODE` и `ENABLE_R503S` работает только отпечаток — PIN-код исключается из сборки.
  - При `ENABLE_PIN_CODE` показывается экран блокировки с полем ввода и цифровой клавиатурой `0–9` с клавишей **Enter**.
  - При `ENABLE_R503S` показывается экран ожидания отпечатка: заголовок, иконка-кольца, крупный статус (`READY` / `SCAN` / `MATCH` / `DENIED` / `OFFLINE`) и подсказки. Успешное распознавание сменяет его списком аккаунтов.
  - Цифры по мере ввода появляются в поле ввода (до 8 символов).
  - **Enter при верном пине** — разблокировка устройства, переход к списку аккаунтов.
  - **Enter при неверном пине** — поле ввода очищается, процесс ввода начинается заново.
  - **Clear** — кнопка внизу экрана очищает введённые цифры без проверки и оставляет устройство заблокированным.
  - Пин-код задаётся константой `PIN_CODE` в `src/credentials.h`.
  - **Светодиод R503:** синий, пока устройство заблокировано; мигает фиолетовым, когда палец приложен; коротко зелёный при успехе, красный при отказе; после разблокировки не горит.
  - **Касание датчика включает подсветку экрана**, если она погашена.
  - Через 30 секунд бездействия подсветка гаснет; при `ENABLE_R503S` устройство при этом снова блокируется, как при включении.
  - Для R503-S используются заранее сохранённые в датчике шаблоны. Если датчик недоступен, устройство остаётся заблокированным.

- **🛠 Служебный режим управления отпечатками**
  - Вход: удерживайте **правую кнопку** при включении, затем введите пин-код на сенсорной клавиатуре.
  - Запись новых пальцев с именем, проверка приложенного пальца, список сохранённых шаблонов, удаление одного шаблона и полная очистка.
  - Выхода нет: чтобы вернуться к обычной работе, перезагрузите устройство.
  - Отключается макросом `ENABLE_SERVICE_MODE` в `src/T-DISPALY_passwordBox.cpp`.

- **📋 Интерфейс выбора аккаунта**
  - Сенсорный экран: строки списка занимают всю ширину и идут без зазоров — попасть пальцем можно в любую точку строки. Выбранный аккаунт подсвечен акцентом, остальные — тёмные карточки в общем стиле экранов; по умолчанию выбран первый.
  - Физические кнопки: **короткое нажатие левой кнопки** — ввод логина, `TAB`, пароля, `Enter`; **короткое нажатие правой кнопки** — только пароль и `Enter`; **долгое нажатие** — только пароль (правая) или только логин (левая).
  - Запись с логином `nologin` при коротком нажатии любой кнопки вводит только пароль и `Enter`.

- **⌨️ USB HID клавиатура** — устройство имитирует клавиатуру через USB-C.

- **🐭 Анти-блокировка (опционально)** — автодвижение мыши каждые 60 секунд для предотвращения перехода системы в спящий режим (`#define ENABLE_MOUSE`).

- **🔆 Автоотключение подсветки** — через 30 секунд бездействия подсветка гаснет, любое касание возвращает её. Нажатие физических кнопок при погашенной подсветке игнорируется и подсветку не включает.

## 🛠 Аппаратное обеспечение

- **Плата:** LilyGo T-Display S3 (ESP32-S3)
- **Экран:** Встроенный TFT, 170×320 пикселей
- **Сенсор:** CST816 (емкостный тачскрин)
- **Опционально:** датчик отпечатка R503-S с UART-интерфейсом
- **Подключение R503-S:** красный +3.3 В, чёрный GND, белый TX→GPIO 1, зелёный RX←GPIO 2, синий WAKEUP→GPIO 3 (низкий уровень, пока палец на сенсоре)
- **Подключение:** USB Type-C

## ⚙️ Настройка

1. **Подготовка данных:**
   - Скопируйте файл `src/credentials.example.h` в `src/credentials.h`.
   - Если используется PIN, задайте его в константе `PIN_CODE` локального файла `src/credentials.h`.
   - Заполните массив `credentials` своими данными. Пример:
     ```cpp
     Credential credentials[] = {
       {"Name",   "your_login", "your_pass"},
       {"Mail",   "user@mail.ru", "some_pass"},
       {"PinOnly", "nologin",    "pin_only_entry"},
     };
     ```
   - Логин `nologin` означает, что для этого аккаунта вводится только пароль.

2. **Подключение R503-S** (для разблокировки отпечатком):
   - `TX` датчика (жёлтый) → `GPIO2`, `RX` датчика (коричневый/зелёный) → `GPIO1`, `GND` — общий.
   - Питание — только 3,3 В: красный `VCC` и белый `3.3VT` на `3V3`. Входы ESP32-S3 не должны получать больше 3,3 В.
   - **Не используйте GPIO16 и GPIO21** — это `INT` и `RST` тач-контроллера CST816: UART на этих линиях ломает тач и дёргает сброс контроллера. Свободные выводы платы: 1, 2, 3, 10–13, 43, 44.
   - Скорость UART в прошивке — 57600 бод. При инициализации уровень безопасности сенсора выставляется в 3, а совпадение принимается только при счёте ≥ 55 (`R503_MIN_CONFIDENCE`).
   - Отпечатки записываются в память R503-S отдельной прошивкой — проектом `T-DISPLAY-TOUCH_fingerprints_R503-S`. Эта прошивка только читает шаблоны; регистрация с экрана устройства не поддерживается.
   - Сборка не требует правок в `.pio/libdeps`: конфигурация TFT_eSPI лежит в `include/tft_setup.h` (панель на 8-битной параллельной шине), драйвер тача CST816_TouchLib 1.0.1 — в `lib/`.

3. **Включение/отключение функций** (файл `src/T-DISPALY_passwordBox.cpp`):
   ```cpp
   #define ENABLE_PIN_CODE   // раскомментировано = запрос пин-кода при запуске
   // #define ENABLE_R503S   // раскомментируйте для разблокировки отпечатком
   // #define ENABLE_MOUSE    // раскомментируйте для автоматического движения мыши
   ```
   Одновременно активен только один способ: если включены оба макроса, работает только `ENABLE_R503S`, а поддержка PIN-кода исключается из сборки (в логе будет предупреждение).

4. **Сборка и прошивка:**
   - Установите [PlatformIO](https://platformio.org/).
   - Соберите проект (`pio run`) и залейте прошивку (`pio run -t upload`).
   - Настройки платы и библиотек уже указаны в `platformio.ini`.

## 🧰 Использование

1. Подключите устройство к компьютеру через USB-C.
2. Разблокируйте устройство:
   - **PIN** (только если включён `ENABLE_PIN_CODE`, а `ENABLE_R503S` выключен): введите цифры на сенсорной клавиатуре и нажмите **Enter**; **Clear** очищает поле.
   - **R503-S** (если включён `ENABLE_R503S`): приложите палец, заранее зарегистрированный в датчике. Светодиод мигает фиолетовым во время проверки, коротко зелёный — успех, красный — отказ. Касание датчика включает подсветку. При отсутствии связи список аккаунтов не открывается.
   - Через 30 секунд бездействия подсветка гаснет; при `ENABLE_R503S` устройство при этом блокируется заново, как при включении.
3. После разблокировки выберите нужный аккаунт касанием экрана.
4. Нажмите физическую кнопку:
   - **Короткое нажатие левой кнопки** — устройство введёт логин, нажмёт `TAB`, введёт пароль и нажмёт `Enter`.
   - **Короткое нажатие правой кнопки** — устройство введёт только пароль и нажмёт `Enter`.
   - **Долгое нажатие** — правой кнопкой вводится только пароль, левой — только логин.

## 🛠 Служебный режим: управление отпечатками

1. Зажмите **правую кнопку** и, удерживая её, включите или перезагрузите устройство.
2. Отпустите кнопку, когда появится экран `SERVICE / ENTER PIN`, и введите пин-код из `PIN_CODE`.
   - Неверный пин — поле очищается, можно повторить. Выйти из экрана ввода можно только перезагрузкой.
3. В менеджере доступно:
   - **ADD FINGER** — выбрать палец из списка, приложить его дважды, шаблон сохраняется в датчик с именем;
   - **CHECK FINGER** — проверить палец: вердикт, номер шаблона, имя и достоверность;
   - **STORED LIST** — список сохранённых шаблонов, удаление одного или очистка всех;
   - **INFO / TEST** — состояние датчика, счётчики съёмки, живой индикатор синего провода и проверка координат тача.
4. Для возврата к обычной работе перезагрузите устройство: выхода из режима нет.

Записанные здесь шаблоны сразу используются экраном блокировки после перезагрузки — это те же данные во флэш-памяти датчика.

## 🩺 Диагностика

Монитор порта (`pio device monitor`) показывает команды светодиода и результат проверки:

```
[r503] led func=3 color=2 -> 0x00      # дежурный синий, модуль принял команду
[r503] led func=2 color=3 -> 0x00      # мигание фиолетовым при приложенном пальце
[r503] search 0x04 -> 0x00 id=3 conf=96
```

| Симптом | Причина и что делать |
|---|---|
| Светодиод залип зелёным/красным, индикация не меняется | Команда «выключить» раньше уходила с недопустимым цветом и отключала индикацию навсегда — исправлено, дежурное состояние переотправляется раз в 5 с. Если в логе `0x01`/`0x03` на каждой команде, модуль не поддерживает Aura LED — работает только индикация на экране. |
| Касание не включает подсветку с первого раза | Касание приходилось на момент съёмки отпечатка, когда цикл был заблокирован. Теперь тач опрашивается и во время съёмки. |
| После разблокировки и сна шрифты стали огромными, слова не влезают | Экран аккаунтов выставляет `setTextSize(3)`, а `drawString(font)` масштабируется текущим размером; `tft.init()` его не сбрасывает. Теперь экран блокировки принудительно ставит `setTextSize(1)`. |
| Подсветка включается с задержкой после касания датчика | Раньше экран будился после ответа по UART. Теперь используется синий провод WAKEUP (GPIO 3): прерывание по фронту вниз включает подсветку в момент касания. |

## 📂 Структура проекта

```
├── src/
│   ├── T-DISPALY_passwordBox.cpp   # Основной режим: блокировка, интерфейс, HID
│   ├── fp_manager.cpp              # Служебный режим: управление отпечатками
│   ├── credentials.h               # Твои логины/пароли и пин-код (не в git)
│   └── credentials.example.h       # Шаблон для credentials.h
├── include/
│   ├── config.h                    # Пины и параметры R503-S
│   ├── app_shared.h                # Общие объекты дисплея и тача
│   ├── fp_manager.h                # Вход в служебный режим
│   └── tft_setup.h                 # Конфигурация TFT_eSPI для этой платы

└── platformio.ini  # Конфигурация PlatformIO
```

## ⚠️ Важные замечания

- Пароли и пин-код хранятся в файле `src/credentials.h`. Обязательно сохраняйте этот файл в безопасности — он добавлен в `.gitignore` и не попадает в репозиторий.
- Пример пин-кода в `credentials.example.h` (`12345678`) — не используйте его в реальном устройстве.
- Убедитесь, что `credentials.h` создан и настроен до первой сборки.

## 🧭 Разработка через OpenSpec

Требования к поведению устройства поддерживаются в `openspec/specs/`; конфигурация и контекст проекта находятся в `openspec/config.yaml`. При изменении требований сначала опишите изменение через OpenSpec, затем реализуйте его и синхронизируйте итоговые спецификации.

В проекте настроены команды OpenSpec для GitHub Copilot:

1. `/opsx:explore` — изучить задачу и варианты решения.
2. `/opsx:propose "описание изменения"` — создать предложение и артефакты изменения.
3. `/opsx:apply` — реализовать задачи изменения.
4. `/opsx:archive` — завершить изменение и перенести требования в основные спецификации.
5. `/opsx:sync` — применить delta-спецификации изменения к основным спецификациям без архивации.
6. `/opsx:update` — доработать артефакты существующего изменения, не трогая код.

Для проверки спецификаций используйте `openspec validate --specs`. Сборка прошивки проверяется отдельно командой `pio run`. После инициализации OpenSpec может потребоваться перезапустить IDE, чтобы команды Copilot появились в чате.
