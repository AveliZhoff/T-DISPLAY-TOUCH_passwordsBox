# Design

## Context

На заблокированном экране касание сейчас включает подсветку, а затем всегда передаёт координаты PIN-клавиатуре. См. [proposal.md](./proposal.md) и [specs/pin-code-lock/spec.md](./specs/pin-code-lock/spec.md).

## Goals / Non-Goals

**Goals:**
- Различать касание для пробуждения и касание для взаимодействия с PIN-клавиатурой.
- Сохранить текущее обновление таймера бездействия при касании.

**Non-Goals:**
- Менять обработку касаний после разблокировки.
- Менять таймаут подсветки или экранную клавиатуру.

## Decisions

- Считать подсветку выключенной на момент получения события касания достаточным признаком касания-пробуждения. Для каждого события касания получить координаты, чтобы потребить событие в CST816, затем включить подсветку и обновить `timeStamp`. Передавать координаты PIN-клавиатуре только если подсветка была включена до касания.
- Не добавлять отдельное состояние или таймер: текущий флаг подсветки и таймер бездействия уже определяют требуемый переход.

Библиотека CST816 сбрасывает признак ожидающего касания только при чтении координат через `getLastTouchPosition()`. Поэтому событие пробуждения необходимо потребить, даже если его координаты не используются для ввода.

## Risks / Trade-offs

- [Пользователь ожидает ввода PIN первым касанием после пробуждения] → касание-пробуждение намеренно требует отдельного следующего касания для нажатия клавиши, как определено спецификацией.
