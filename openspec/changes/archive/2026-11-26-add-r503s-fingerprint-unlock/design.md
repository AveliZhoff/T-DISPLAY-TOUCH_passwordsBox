# Design

## Context

Сейчас экран блокировки, состояние `deviceUnlocked` и обработка касаний существуют только под `ENABLE_PIN_CODE`; при отсутствии этого флага список показывается сразу. R503-S должен работать как альтернативный способ аутентификации, не меняя существующий ввод PIN. См. требования в `specs/fingerprint-unlock/spec.md` и `specs/pin-code-lock/spec.md`.

## Goals / Non-Goals

**Goals:**
- Объединить PIN и отпечаток общим состоянием блокировки и оставить отображение списка за успешной аутентификацией.
- Изолировать код и аппаратную инициализацию R503-S макросом `ENABLE_R503S`.
- Выполнять сопоставление отпечатка средствами датчика по шаблонам, уже сохранённым в его памяти.

**Non-Goals:**
- Добавлять на устройстве интерфейс регистрации, удаления или управления шаблонами отпечатков.
- Менять поведение ввода PIN, выбора учётных записей или USB HID после разблокировки.
- Разрешать доступ при ошибке связи с датчиком.

## Decisions

- **Общий compile-time шлюз блокировки.** Условие защиты списка определяется наличием `ENABLE_PIN_CODE` или `ENABLE_R503S`; при отсутствии обоих макросов сохраняется текущий путь без блокировки. Это позволяет не дублировать состояние блокировки и изоляцию HID.
- **Сохранить методы независимыми.** PIN-экран остаётся доступен при `ENABLE_PIN_CODE`; R503-S выполняет распознавание при `ENABLE_R503S`. Если заданы оба флага, успешен любой метод. Альтернатива — заменять PIN при включённом датчике — отвергнута, чтобы не ломать существующую настройку и оставить резервный путь.
- **Использовать внутреннее сопоставление R503-S.** Прошивка запрашивает у датчика результат сравнения отпечатка с заранее записанными шаблонами; регистрация и хранение шаблонов в MCU не добавляются. Обработчик или библиотека обмена выбираются после проверки совместимости с PlatformIO и Arduino-ESP32.
- **UART только на свободных GPIO 1/2.** Разводка платы проверена: GPIO16 и GPIO21 — это INT и RST тач-контроллера CST816 (библиотека CST816_TouchLib использует их по умолчанию), GPIO 5–13 и 38–48 заняты дисплеем, 15 — питанием периферии, 0/14 — физическими кнопками, 4 — ADC батареи. Поэтому TX датчика идёт на GPIO2, RX — на GPIO1. Первая редакция прошивки назначала 21/16 и работать не могла: UART оказывался на линиях тача, а импульсы данных попадали на вход `reset` тач-контроллера.
- **Поиск 1:N — команда `0x04`, `0x1B` только как фолбэк.** Проверено на живом R503-S: быстрый поиск (`0x1B`) на этом экземпляре отвечает `OK` с пустым payload, и библиотека Adafruit, читая остатки предыдущего пакета, сообщает «совпадение ID 0 / score 0» на любой палец. Поэтому поиск идёт `fingerSearch()` (0x04), при мусорном ответе выполняется одна попытка `0x1B`, а совпадением считается только ответ с валидным ID (не `0xFFFF`) и ненулевым счётом.
- **Порог счёта и уровень безопасности.** При инициализации уровень безопасности сенсора выставляется в 3, разблокировка требует счёт не ниже `R503_MIN_CONFIDENCE` (55). Это исключает разблокировку «слабым» совпадением и ложные срабатывания на чужой палец.
- **Съёмка после паузы, временный `0x02` терпится.** Первый кадр после касания смазан, поэтому кадр снимается через 200 мс, а ответ «нет пальца» (`0x02`) при прижатом пальце повторяется до трёх раз и только затем считается уходом пальца.
- **Конфигурация дисплея и тача — в репозитории.** TFT_eSPI настраивается через `include/tft_setup.h` и `-DUSER_SETUP_LOADED` (панель висит на 8-битной параллельной шине, не на SPI), а CST816_TouchLib 1.0.1 вендорена в `lib/`. Без этого сборка из чистого клона зависела от ручных правок в `.pio/libdeps` и от версии библиотеки в реестре, где осталась только 2.x с переименованным API.
- **Ошибки датчика закрывают доступ.** Ошибку инициализации или связи показывать на экране, сохраняя блокировку; продолжать периодически опрашивать датчик можно только если это поддерживается выбранным драйвером без сброса состояния блокировки.
- **Активен только один способ разблокировки.** `ENABLE_PIN_CODE` и `ENABLE_R503S` взаимоисключающие: при одновременном включении прошивка исключает PIN-код (`#undef`) и работает только по отпечатку. Это убирает неоднозначность «любой из двух методов» и лишний код в сборке.
- **Светодиод R503 — индикатор состояния.** Синий в заблокированном состоянии, мигание фиолетовым при проверке, короткий зелёный при успехе и красный при отказе, выключен после разблокировки. Состояние светодиода обновляется только при его изменении, чтобы не забивать UART командами.
- **Экран блокировки в стиле проекта `T-DISPLAY-TOUCH_fingerprints_R503-S`.** Тёмный фон, заголовок, иконка-кольца отпечатка, крупный статус (READY/SCAN/MATCH/DENIED/OFFLINE) и строки подсказок; перерисовывается только при смене состояния.
- **Касание датчика будит подсветку.** Обнаружение пальца в цикле съёмки включает подсветку и продлевает таймер простоя — так же, как касание экрана.
- **Гашение подсветки повторно блокирует устройство.** При `ENABLE_R503S` таймаут простоя переводит устройство в состояние «как при включении» и снова включает синий светодиод.
- **Опрос тача во время съёмки.** Съёмка отпечатка блокирует цикл до нескольких сотен миллисекунд; паузы внутри выполняются через цикл опроса тача, иначе касание в это окно теряется и подсветка не включается с первого раза.
- **Светодиод подтверждается периодически.** Если команда Aura LED потерялась или модуль её проигнорировал, дежурное состояние переотправляется раз в 5 секунд; команда «выключить» идёт с допустимым цветом и дублируется командой 0x51.
- **Подсветка включается по сигналу WAKEUP, а не по ответу UART.** Синий провод датчика (GPIO 3) держится в низком уровне, пока палец на сенсоре; прерывание по фронту вниз ставит флаг, который проверяется в главном цикле и в паузах съёмки. Задержка включения подсветки — единицы миллисекунд вместо 200+ мс ожидания ответа `getImage`.
- **Размер шрифта задаётся явно на каждом экране.** `drawString(..., font)` масштабируется текущим `textsize`, а `tft.init()` его не сбрасывает, поэтому экран аккаунтов (`setTextSize(3)`) «протекал» в экран блокировки — шрифты становились втрое больше, слова не влезали. Экран блокировки и кадр статуса принудительно ставят `setTextSize(1)`, подсветка списка — `3`.

## Risks / Trade-offs

- [Неизвестны фактические провода и свободные UART GPIO конкретной сборки] → разводка проверена по схеме платы и подтверждена на устройстве: свободны GPIO 1, 2, 3, 10–13, 43, 44; линии 16/21 принадлежат тачу. Итоговая схема описана в README.
- [Прошивка клона R503-S может не поддерживать часть команд] → поиск 1:N выполняется классической командой `0x04` с фолбэком на `0x1B`, ответ «OK» без данных не считается совпадением, а достоверность подтверждается порогом счёта.
- [Выбор сторонней библиотеки может добавить несовместимость или лишнюю зависимость] → сначала проверить доступный UART API датчика, совместимость с Arduino-ESP32 и сборкой PlatformIO; добавлять зависимость только при необходимости.
- [Незарегистрированный палец или отказ датчика оставит устройство заблокированным] → при одновременном включении PIN и R503-S PIN остаётся альтернативой; при fingerprint-only режиме показывать понятную ошибку, не открывая список.
- [Шаблоны предварительно зарегистрированы вне прошивки] → явно документировать это ограничение и не обещать регистрацию через интерфейс устройства.

## Migration Plan

1. Сохранить PIN-only конфигурацию без изменения пользовательского поведения.
2. По умолчанию оставить `ENABLE_R503S` выключенным; для сборки с датчиком включать его явно и подключать датчик к выбранным UART GPIO.
3. Проверить конфигурации без блокировки, только с PIN, только с R503-S и с обоими способами.
4. Для отката убрать `ENABLE_R503S` и отключить датчик; существующая PIN-конфигурация продолжит работать.
